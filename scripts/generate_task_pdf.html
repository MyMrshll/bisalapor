1 Fokus Khusus Frontend & Prinsip Mock Architecture

Sesuai arahan proyek saat ini, fokus pengerjaan adalah 100% pada Frontend (UI, UX, Interaktivitas, dan Responsivitas) tanpa mengintegrasikan backend atau database terlebih dahulu. Strategi ini memungkinkan tim bergerak cepat menghasilkan produk frontend yang siap pakai dan dapat didemokan secara mandiri.

  • Mock Data Architecture: Seluruh data pekerjaan (Work Orders), laporan, draf AI, dan pesan inbox disuplai melalui file TypeScript/JSON mock lokal (misal: src/mocks/workOrders.json).
  • Client-Side State Management: Operasi filter, pencarian (search debounce), penambahan WO, dan pergantian status (misal: tombol Approve Report) ditangani langsung di state aplikasi (React State / Zustand / Context).
  • Kemandirian Modul: Tidak ada developer yang tertunda oleh pembuatan API backend, migrasi database, atau setup server eksternal.

5 Standar Kualitas Frontend (Definition of Done)

Area Kualitas Standar yang Wajib Dipenuhi
Responsivitas Semua halaman wajib tampil sempurna dari viewport smartphone (360px), tablet (768px), hingga desktop (1440px). Tabel di mobile otomatis beralih ke Card View.
State Handling Setiap modul wajib menangani 5 kondisi UI: Loading (skeleton), Empty state (data kosong), Error state (gagal fetch), Permission denied, dan Success feedback (Toast).
Data Layer 100% menggunakan Mock Data Typescript/JSON lokal. Tidak boleh ada dependency ke server backend eksternal yang belum siap.
Git Branching Format branch: feat/<dev-name>-<modul> (misal: feat/dev2-work-orders). Wajib lolos linter & typecheck sebelum pull request.
